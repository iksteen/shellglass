# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

shellglass mirrors an interactive command (run in a PTY, the `script(1)` model) as live HTML in a browser: terminal state lives in a long-lived `vt100` parser and is pushed to the browser over SSE (no polling, no per-tick subprocess). Read `README.md` for the user-facing model — this file covers the internals.

## Commands

```sh
cargo build --release            # full binary + per-mode bins at ./target/release/
                                 # (shellglass, shellglass-{serve,push,attach,hub,sessions,recordings,keytool})
cargo check --no-default-features --features hub   # modes are cargo features —
                                 # hub/serve/push/serve-api/push-api subset builds must stay
                                 # warning-free (CI matrix)
cargo run --example external-source --features serve-api   # library API, no PTY
cargo test --workspace           # unit tests incl. vendored vt100 suite (CI runs with --locked)
cargo test id_is_deterministic   # a single test by name
cargo fmt --all --check          # CI gate
cargo clippy --workspace --all-targets -- -D warnings   # CI gate (pedantic-clean; keep it that way)

cd viewer && npm ci              # once: browser-renderer toolchain (TypeScript)
npx tsc --noEmit                 # type-check viewer.ts (CI gate)
node --test                      # viewer unit tests (CI gate)
npm run build                    # regenerate viewer/dist/viewer.js — COMMIT IT after
                                 # editing viewer.ts (CI fails if dist drifts)
```

`cargo build` works without Node: `build.rs` compiles `viewer/viewer.ts` with the local `tsc` when `viewer/node_modules` exists, else it bakes the committed `viewer/dist/viewer.js`.

CI (`.github/workflows/ci.yml`) runs fmt + clippy + tests plus the viewer job (type-check, tests, dist-freshness) on push/PR. Tagging `v*` triggers Docker Hub multi-arch and GitHub Release binary builds (both consume the committed `dist/`, no Node).

## Architecture

The core is one streaming pipeline shared by every mode:

```
PTY output bytes → vt100::Parser → model::Grid (StyledCell cells)
  → source::SourceSession (watch::Receiver<Arc<Frame>>)
  → diff::Live (rectangle deltas, encoded once)
  → SSE → viewer.js renders cells → HTML in the browser
```

Everything downstream of `SourceSession` is producer-agnostic: `source.rs` is the
boundary (frame receiver + a `SinkStatus` for hub outage notices), so an external
capture backend can drive the whole stack through `api.rs` (see **Key layers**).

**Input backend** — `pty.rs` (started from `main.rs`; in push mode only after the first successful hub registration, so a down hub retries before the command runs) produces a `SourceSession` of structured screen snapshots (`Frame::Screen(Grid)`). It runs one command in a PTY (`script(1)` model); one parser, one screen. A single `screen` thread owns raw mode + stdout + parser so hub-connection notices can pause/repaint cleanly, and snapshots at a 30fps cap (`MIN_FRAME`), holding frames during a synchronized
update (DEC 2026, `SyncGate`) with a 1s deadline so viewers never see a torn
mid-redraw snapshot and a stuck BSU can't freeze the mirror. The command defaults to `$SHELL`; `SIGWINCH` (Unix) or console-size polling (Windows/ConPTY) reflows both the PTY
and the parser.

The `screen` thread also runs the inline-image side channel (`images.rs`): raw PTY bytes go through an `Interceptor` whose `feed` returns ordered `Step`s — a flat enum where each variant names its own sinks (`Step::tee()` is the single source of truth for what reaches the terminal). `Passthrough(bytes)` → local terminal AND vt100; `TerminalOnly(bytes)` → terminal only (a mid-flight chunk, a non-display action, an over-cap image, vt100 never sees it); `Image`/`Deferred(bytes, …)` → terminal renders the bytes natively while the mirror stamps a placement at the cursor; `Delete(bytes, sel)` → the emitter revoked placements it made earlier (kitty `a=d`) and the mirror drops the ones `sel` names; `Reject(resp)` → a refused kitty **file/shm** transmission (its path/name payload is an arbitrary-file exfiltration vector on the untrusted stream) — SUPPRESSED from the terminal (`tee()` is `None`), and `resp` (a kitty error echoing the request id) is injected to the app via the shared PTY writer so a detect-mode client (`kitten icat`) concludes the medium is unsupported and resends via direct transmission, which we DO mirror: the hole is closed without losing images on the web. Because the interceptor drives the local tee (rather than a blind verbatim write), a rejected sequence can be withheld before the terminal ever services it — the price is a one-reassembly buffering delay on image sequences (text still flushes at once), invisible because terminals render an image on its terminator anyway. A placed image is tracked with **per-cell image tags** — the vendored vt100's `place_data_with` stamps `(id, row_off, col_off)` into every covered cell, and vt100's own scroll/reflow/erase then manage the image's lifetime. Two lifetimes, per `PlaceOpts`: a plain tag dies with the cell's contents (set OR clear) like a cell-based sixel terminal erases an image, while a **sticky** tag (kitty placements) survives text drawn over it AND an erase of that text, dying only with a whole-display erase (`CSI 2 J` — the one place kitty's erase paths call `grman_clear`) or a scroll out of the grid. kitty keeps a placement until it is deleted, and an emitter that repaints or clears the lines under its image (zellij, whenever a pane redraws) would otherwise lose it from the mirror while the terminal still shows it. Each frame `resolve_images` reconstructs the top-left from the most top-left surviving tag (its stored offset makes any survivor exact; a bottom-row survivor yields a negative row → viewer clips) and evicts once no covered cell is left. The cursor is left on the image's last row (where a sixel-scrolling terminal leaves it) — unless the placement HOLDS it (kitty `a=p,C=1`, which zellij emits after positioning the cursor itself): `place_data_held` then stamps downwards without moving the cursor and without scrolling, clipping at the last row. Heavy decodes (sixel, kitty raw) are DEFERRED: the placement stamps immediately (dims from raster attributes/metadata), a worker thread decodes+encodes off the screen thread (newest-wins per LINEAGE — an animation replacing itself at the cursor is lineage 0, while each kitty `(image, placement)` pair is its own, so simultaneous placements don't supersede each other) (so a sixel video can't stall the tee; skipped jobs = the backpressure signal that drops PNG to fast compression), and a pending placement is invisible in frames until `Msg::ImageReady` fills it. Flicker-free swap: a ready image overwritten by a still-pending successor stays emitted as a ZOMBIE (frozen coords) until the successor's bytes land — frames never flash image-less mid-video; the viewer bridges its own fetch gap the same way (`heldImages`). Placements ride the frame as `Grid::images` (position/size + the payload's content address, plus the sub-cell offset and stacking order an emitter states); the payloads themselves ride `Grid::image_data`, producer-side only.

**Three serving modes** (dispatched in `cli.rs`; every binary — the full multi-call `shellglass` and the per-mode ones in `src/bin/` — wraps the same clap actions there; modes are cargo features). Each mode's feature splits in two: `serve` = `mirror` + `serve-api`, `push` = `mirror` + `push-api`, where `mirror` is the built-in PTY/vt100 producer (`vt100` itself is optional) and the `-api` half is the transport + `presentation` (fonts/config/template) an external producer links on its own:
- Standalone (`server.rs`) — local axum server: `GET /` page, `GET /events` SSE deltas, `GET /viewer.js` the baked renderer.
- Client (`client.rs`) — keeps the previously-sent frame and streams `diff.rs` wire messages to a remote hub over one `/push` **WebSocket**: a `RegisterBody` (page-scoped base CSS, structured font assets, render-config) as the first message, then a full picture on each (re)connect, then only deltas (a resize is a layout change, which `encode_delta` turns into a full). It never sends font CSS or configured family names: the regular face's content hash is the `family_key`, bold faces reference the same key, and hub-mode CSS/render config use that hash as the family alias. Pings for liveness (a run of unanswered pongs, or a send stalled past a timeout, ⇒ dead ⇒ reconnect — so a black-holed hub is caught in seconds, not the kernel's ~15-min TCP timeout). Re-registers + reconnects on ordinary drops; the protocol-2 private replacement Close is fatal, because reconnecting an evicted client would steal the session back and create an eviction loop.
- Hub (`hub.rs`, `hub` subcommand) — renders nothing and re-diffs nothing; the `/push` WebSocket runs a `AwaitingRegister → Streaming` state machine (first message = register, rest = wire messages), authorized once at the upgrade. Exactly one push connection owns a session: a newly negotiated connection atomically evicts the incumbent with the protocol-2 replacement Close, and serial-checked cleanup prevents the old connection from marking its replacement offline. Stores each client's pushed base CSS/render-config for the normal session page, generates font CSS from structured metadata, applies each pushed wire message to the session's full matrix (`diff::Live::publish_wire`) and forwards the bytes to viewers verbatim; serves viewers at the canonical `/s/<slug>/` (slash-less form 308s with a RELATIVE Location). Normal pages use the pushed template when present, otherwise the hub's built-in or `--template` fallback; `--force-template` makes the fallback and the raw presentation authoritative, discarding pushed template/CSS/render JSON and using hub-generated CSS/config instead. Validated hash-keyed fonts remain available in that generated presentation; no client-authored font CSS or family name is reproduced. Hub-owned templates get a per-response `{{nonce}}`, nonce-stamped boot scripts, sanitized render JSON, and a matching script CSP. **Every hub embed presentation is hub-owned**: `?embed` uses the built-in template plus generated base CSS/config, and iframe-less `config`/`style.css` expose only generated config/font rules; pushed CSS, template, and render JSON never enter an embed response. Verified regular font hashes may select uploaded fonts, but all CSS syntax and other presentation values are hub literals. **Pages are subpath-mountable**: every asset/SSE URL a page carries is relative (`events`, `fonts/<key>`, `viewer.js`, `favicon.svg` — the latter two routed per slug too), because a reverse proxy may mount the hub under a prefix neither the hub nor the client can know. **Fonts are content-addressed and deduplicated hub-wide** (`FontCache`): the HUB accepts only known font MIME types, derives `proto::content_key` = `sha256(mime·0·bytes)`, and accepts a `family_key` only when it is exactly a lowercase 64-character hash owned by an uploaded regular face (a regular must claim its own derived key; bold may reference that key). It derives the fixed `format()` token and emits the complete `@font-face`, so neither free-form font names nor font CSS cross the wire. Inline-image blobs are likewise byte-sniffed to PNG/JPEG/GIF/WebP and served with the canonical MIME + `nosniff`; claimed HTML/SVG never becomes a same-origin asset. Each `Session` holds a reference SET that is both the refcount stake (`retarget_fonts` diffs it on register/delete; zero-ref entries evict) and the serving authorization (`/s/<slug>/fonts/<key>` serves only that session's own keys — shared storage, per-session namespace). Content addresses never change meaning ⇒ font responses are `immutable`, cached a year. The standalone serve path still uses configured family names and generates its complete CSS locally. The hub's LOG is the authority on view URLs (`view_base`: X-Forwarded-Proto/Host/Prefix); push deliberately prints none. On SIGTERM it Closes every push WebSocket (see `main`'s graceful path) so pushers reconnect promptly instead of black-holing.

**Key layers:**
- `model.rs` — parser-agnostic in-memory IR (`StyledCell`, `Grid`, `Frame`); `Color` and `ImagePlacement` carry serde (embedded in the wire — cell styles, and the full frame's `i` list). Nothing here depends on `vt100`. `Grid::source_epoch` is producer-only (never on the wire): changing it forces a full frame, which is how an external producer switching sources resets state a same-layout diff would otherwise carry over — notably the append-only OSC 8 link table.
- `source.rs` — the producer boundary. `SourceSession` = frame receiver + `Arc<dyn SinkStatus>` (hub down/up; the PTY's impl pauses and repaints the terminal it owns, `NoopSinkStatus` for a producer that merely observes someone else's). `external_source()` hands back a newest-wins `FramePublisher` (`publish`, and `switch_source` to bump the epoch). Unconditionally compiled — it is just the IR's transport contract.
- `api.rs` — the library embedding surface (feature `presentation`): `Presentation` (config → resolver/fonts/template, what `cli.rs`'s `setup` used to be), `serve`/`serve_with_shutdown` + `ServeOptions` (feature `serve-api`), `push` + `PushOptions` (feature `push-api`). The CLI runs through these, so library and command line cannot drift — the same rule the clap surface in `cli.rs` follows. Option structs are `#[non_exhaustive]`: build with `::new()`. `docs/library-api.md` is the user-facing version; `examples/external-source.rs` is a runnable synthetic producer.
- `images.rs` — inline-image interceptor. Scans raw PTY bytes for kitty (`_G` APC), iTerm2 (OSC 1337, single-shot + multipart), and sixel (`ESC P … q`) sequences, reassembling ones split across reads, and decodes/normalizes each to a browser-native image (sixel and raw kitty RGB/RGBA → PNG; iTerm2 forwards PNG/JPEG/GIF/WebP; kitty is mirrored both ways round — `a=T` draws at the cursor, and **transfer-then-place** (`a=t` with an `i=` into a byte-capped store, then `a=p` cutting out the `x,y,w,h` SOURCE-pixel rect — already scaled to the destination, so `px / cell` gives the footprint — positioned inside its cell by `X`/`Y` and stacked by `z`; a partial crop of an *encoded* image is decoded/cut/re-encoded on the worker. `a=d` revokes placements, since an emitter that blanks an image without repainting the cells would otherwise leave it on the web: the parser names the selector (`d=i`/`r` by id, `a` all, `c` cursor, `p`/`q`/`x`/`y`/`z` by geometry) and `pty::revokes` matches it against the placement rects — `d=f` touches no placement and `d=n` selects by an image *number* we never resolve, so neither can strand one) — but **only over direct `t=d` transmission** — the file/temp/shm mediums name a filesystem path/shm object that the *untrusted* stream must never make us open, an arbitrary-file exfiltration vector, so they are refused and detect-mode clients fall back to direct). Which protocols to intercept is a startup capability handshake (`probe_caps` in `pty.rs`: kitty query, sixel via Primary DA, iTerm2 via a `TERM_PROGRAM` allowlist; the same fenced handshake reads OSC 10/11 so the viewer uses the outer terminal's actual default colors) — **mirror fidelity is a hard rule**: a protocol the terminal doesn't render passes straight through to vt100, so the web shows exactly what the local screen shows, never more, never less.
- `parse.rs` — `grid_from_screen` extracts a `Grid` from a live `vt100::Screen`.
- `crates/vt100/` — the terminal emulator, vendored from doy/vt100-rust 0.16.2 (upstream
  unmaintained) as a workspace member, with upstream's full fixture test suite running in
  CI. Parser-level fidelity gaps are fixed HERE, not with pre-parser byte shims; every
  local patch is listed in the crate's `Cargo.toml` provenance header (keep it
  current — it is the authoritative patch list) and lands as its own commit so the
  diff against upstream stays reviewable. Planned parser/fidelity work is ordered in
  `docs/roadmap.md` — consult it before starting enhancement work.
- `diff.rs` — the whole wire layer. `Live`: diff-once, broadcast-to-all — the standalone server publishes `Frame`s (delta encoded here, once), the hub publishes the client's already-encoded messages (`publish_wire`: applied to the stored matrix, forwarded verbatim). **Connecting is lock-free** (`/s/<id>/events` is public, so a connect flood must not stall the publisher): deltas are broadcast with a monotonic seq, the current state lives in an `ArcSwap` snapshot with a memoized full encode, and viewers subscribe-then-snapshot, skipping deltas the snapshot covers; each SSE event carries its seq as the `id:` line. Publishers store-before-send — that ordering is the correctness argument. Deltas are **per-line** minimal changed spans as positional tuples `[r, l, text, style?]`; block text merges consecutive single-codepoint glyphs into strings (one cell per codepoint, `0` = blank, `["…"]` = one multi-codepoint-grapheme cell) and styles ride as `[start, len, {attrs}]` runs with `1`-flags (`u` carries the underline-*style* number 1–5 — kitty's `4:n` values, so `1` doubles as the legacy flag for old decoders — with `s` strikethrough and `k` underline color alongside). Rectangles were measured and removed (~5–6× win came from RLE+string-merge; merging lines never paid — see `zz_measure_wire_cost`). Layout (cols/row-count) change ⇒ full frame. Messages carry **no type tag**: each type owns one payload key (`d` full, `r` diff, `c` cell, `l` line, `v` version) with the cursor a separate tri-state `p`, and decode/`apply` dispatch on which key is present (`t` is the window *title*, riding only full/diff shapes — never the `c` form, whose envelope old viewers spread into cell objects where `t` is cell text) — **`c` first**, because the single-cell form flattens its style letters (`f,g,b,d,i,u,s,o,k,n,a,w`) into the envelope and `d`/`w` there must not read as full/wide. Inline images ride the **full** frame only, under key `i` (a list of `ImagePlacement`: position/size + the `k` content address — never bytes; any change to the image set forces a full, and a new/moved/gone image can't ride a per-line diff). The BYTES travel out-of-band: the push client sends a `{"blob":{m,d}}` message BEFORE any frame referencing the payload (WS FIFO = the hub can serve it before any viewer sees the reference; re-sent per connection), the hub intercepts blobs (never forwarded) into a per-session `diff::ImageStore` (byte-capped FIFO; keys the current frame references are eviction-immune), and viewers fetch `images/<k>` over HTTP — immutable, so at high viewer counts the browser/CDN cache absorbs the fan-out that in-frame base64 would multiply per viewer per full.
- `viewer/viewer.ts` — **the** renderer (TypeScript); nothing is painted server-side. Applies full/diff messages to an in-memory cell grid and repaints dirty rows on a **canvas** — the only renderer (the DOM renderer was removed once canvas surpassed it; see `docs/roadmap.md`). Its ground truth is *terminal behavior* (kitty — check its source for placement questions): ink seated inside the cell box (band-clipped per row), run-shaped text (ligatures form; a grid-width guard falls back to per-cell draws), kitty-parity weight boost (double-draw on AA midtones), underline styles 1–5 with kitty's skip-ink exclusion zones, decorations drawn per cell (through spaces), DECSCUSR cursor shapes, crisp device-pixel geometry for box/block/legacy/powerline glyphs, images drawn at their stated stacking order (two passes per row: `z < 0` — and every placement whose emitter states no `z` — under the cells, where a written cell punches its background through; `z >= 0` over them, kitty-style). The DOM underneath holds one transparent single-text-node *ghost row* per line so native select/copy/find work through the `pointer-events:none` canvas: ghost sync patches text nodes IN PLACE via `replaceData` (preserving node identity and Range boundaries), and **the whole picture — canvas and ghost — freezes from pointerdown and while a selection is live** (`pictureHeld`), so what you see, what you highlighted, and what Ctrl-C copies are the same thing; every repaint path — flush, blink timer, hover, cursor travel — respects the hold, release catches both layers up in one step, and default-bg canvas fills are skipped so the selection highlight shows through. **Paint is decoupled from apply**: messages update the grid synchronously; one coalesced `setTimeout(0)` flush (not rAF — rAF suspends in background tabs) paints the union of dirty rows — always the latest state, intermediate frames dropped, like the server's `MIN_FRAME`; canvas frames are cheap so the server's 30fps cap is the only pacing. OSC 8 links have no anchors (ghost text is bare): pointer events map to cells by grid arithmetic — hover underlines the link's cells kitty-style, click opens the `linkHref`-allowlisted URI. `viewer/verify.py` (headless-Firefox screenshot rig) checks terminal semantics on the canvas pixels plus per-`?mode` green/red self-checks; `viewer/bench.py` measures paints/sec under synthetic loads. The default template's footer shows live stats (`#sg-stats`: throughput · fps). Inline images (the full frame's `i` list) are hidden `<img>` elements (stylesheet rule, never inline style, so copied fragments paste visible) fetching the page-relative `images/<k>` content address, whose bitmaps draw on the canvas; on load each swaps its `src` to a `toDataURL` data: URL (guarded against the re-fired load) so a copied fragment embeds the actual bitmap — the HTTP URL dies with the session; each is inserted as a **sibling right after its anchor row** so document order matches visual order — a selection spanning the image's rows carries it into the clipboard's HTML flavor. Pages ship an empty `#screen`; the first SSE event after the version hello is always a full frame, so the initial paint lands one round-trip in. `build.rs` compiles it (local `tsc`, else the committed `viewer/dist/viewer.js`), bakes it in via `include_str!`, and both servers serve it at `/viewer.js`.
- `render.rs` — page assembly only (no cell rendering): fills the page template, builds `@font-face` CSS and the render-config JSON handed to the browser, and carries the baked `viewer.js`/favicon assets + the `viewer_tag()` content hash. Also the **embedding surface**: `?embed` on any view route serves `EMBED_TEMPLATE` (chrome-less, fit-to-frame via `transform: scale` + the `sg-zoom` re-raster event — transform, never CSS `zoom`, because mobile WebKit's text autosizer boosts text zoom makes tiny, ignoring `text-size-adjust`; own offline takeover; a pusher's custom template deliberately never applies). Both built-in templates mount the canvas in a non-transformed `#sg-canvas-host` box mirroring the scaled rectangle (snapped to whole device pixels) — a FROZEN id the baked viewer bootstrap auto-detects (`MountOpts.canvasHost`) — because WebKit rasterizes a transformed canvas layer at its own density and resamples it through the transform (soft glyphs in Safari); only the transparent ghost rows stay under the transform. And `/embed.js` (`EMBED_JS`) is the STABLE public shim — a CLASSIC script (currentScript is null in modules; classic needs no CORS, though the route sends ACAO * for module loads) that replaces its own `<script data-src="…">` tag with the iframe, plus a `<shellglass-view src="…">` element form. `data-src`, the element name and its `src` are a frozen API (host pages don't update); keep it version-agnostic — everything live happens inside the frame.
- `fonts.rs` — `symbol_map` codepoint→family resolution + locating font files via `fontdb` (extracts a single face from `.ttc`) so viewers render glyphs with no local install. `fc-match` is consulted only to resolve a CSS generic like `monospace`.
- `config.rs` — TOML config (`default_font` stack, `symbol_map`, `template`). There is no `theme` option.
- `proto.rs` — client/hub wire contract.
- `session.rs` — detachable (dtach-style) push sessions, Unix only (`push --detachable`). `start_detached` runs the command in a terminal-less PTY owned by a single core thread — a `pty.rs` `HeadlessScreen`: the same frame builder as the local mirror (text/colors/cursor-bridge fidelity, SyncGate + cursor-hide grace) but no image decoding, since there is no local terminal to probe for capabilities — which tees PTY output to at most ONE attached client and publishes frames at ≤30fps. `attach` connects a real terminal over a framed unix-socket protocol (tag + u32-BE length, capped at `MAX_FRAME_LEN`; hello/resize/input/detach ↔ accepted/rejected/kicked/data): while attached it drives the PTY size (only a GRANTED attach may resize — the core thread owns the one-client policy), on `Ctrl-\` detach the session holds the last size, and `attach --force` evicts the incumbent (told apart from the session ending). Sink writes carry a timeout so a stuck client is dropped, never a frozen mirror; the socket is chmod 0600 (it IS the write capability to the session) and a live socket is refused, not stolen. `daemonize()` is the pre-tokio double-fork behind `push --daemon` (both mains build the runtime manually so the fork happens single-threaded).
- `record.rs` — `--record-dir` session recording (serve + hub): timestamped native streams (`.sgs`, JSONL) that are the push transcript VERBATIM — header, then `[ms,<message>]` lines (register, blobs, wire) — so a recording is self-contained (fonts/template/images ride along) and replayable at full mirror fidelity by anything speaking the wire format. The hub taps its `/push` loop (one file per connection under `<dir>/<session-id>/`, enumerable/retrievable via `/api/…/recordings`; `push --no-record` opts out via an additive register key); serve synthesizes the same shape (register built like the push client's, then snapshot-then-ticks). The writer prints nothing (serve owns the terminal) and each line is one write call. Management and owner share the verbs — list, retrieve, delete — differing only in scope: the management API (`/api/…/recordings[/name]`, Bearer) reaches any session's files by id or slug, while **owners** use `/recordings[/name]` (GET/DELETE) authorized by the SESSION key through the same `authorize` path as `/push` — the key names the session, so those routes carry no id and can't reach another session's files. `recctl.rs` + the `recordings` subcommand/`shellglass-recordings` binary (feature `recordings`) are the first-party owner client; `sessions recordings list|get|delete (--id|--slug)` is the management-side equivalent in `apictl.rs`; the shared mechanics (capped reads, name gate, streamed no-clobber download) live in `cliutil.rs`.

## Capability model (proto.rs)

The **secret key** is the write capability. The **session id** = `hex(argon2id(key))` with a fixed salt (`SALT`) is the read capability that goes in the view URL — one-way, so viewers can't recover the key. The hub screens pushes against its session registry (`authorize` in `hub.rs`, at the `/push` upgrade — one argon2 per connection, semaphore-capped + fail2ban-logged on rejection); it never sees secrets. The registry is seeded from `--allow` and runtime-mutable through the management API under `/api` (Bearer-authorized by `api_id(key)` against `--api-allow` — a SEPARATE salt domain, `shellglass/api-id/v1`, so session and API credentials can't cross; the namespace 404s when unconfigured). Opt-in persistence via `--sessions-file`: every mutation atomically rewrites a versioned JSON file of (id, slug) pairs; on startup a loadable file replaces `--allow` (announced), a missing one is seeded from it, and a corrupt one is a hard error — never a silent re-seed, which could resurrect API-deleted sessions. Every registered session has at least a stub: an unseeded slug serves the built-in operator-offline placeholder that reloads itself when the pusher first registers; deletion (explicitly by-id OR by-slug — two routes, since an un-aliased slug IS the id) kicks the live pusher and drops stored state. `session_id` is intentionally memory-hard — call it once per connection, never per frame. `--id-salt` (optional, hub + gen-key + print-id) appends a per-system extension to BOTH salt domains (`<domain>/<ext>`): same secret, different ids per hub — de-amortizes weak-key dictionaries and unlinks reused keys; empty = byte-identical to the un-extended derivation, so existing ids never move. It must match between the hub and the operator's gen-key/print-id (mismatch fails loud: 403). `push` takes no part in authorization-side derivation: it derives no ids for auth or URLs (auth sends the key, font URLs are page-relative) and prints no view URL (the hub's log is the authority); the one id it does derive — once, in detachable mode — merely NAMES the default local socket/log file, which is fine because the id is the public read capability, not a secret. Protocol-skew handling changed as of `SALT` v6. **Historically** the salt's version suffix was bumped on breaking `diff.rs` changes in the belief it guarded wire skew — but since (as just noted) `push` derives no ids and the HUB hashes the incoming key, a salt bump never gated the *client* at all: it only forced the OPERATOR to re-derive ids and update `--allow` + view URLs. Right after a bump every client 403s until `--allow` is re-derived — indiscriminately, not by client version — and once it is, any client with the right key connects regardless of version. So the bump's "loud 403" was a coordination side effect, not a wire-skew gate, and it churned every operator's ids on what was often a cosmetic wire tweak (v5 gated the register-CSS contract that way; the WebSocket migration kept v4 because a gone endpoint 404s loudly on its own). **Now** the salt versions the id-DERIVATION scheme ONLY (frozen at v6, the last such rotation), and wire skew is caught by explicit **version negotiation**: the push client sends `proto::PROTOCOL_VERSION` in the `x-shellglass-protocol` header alongside its key, and a hub that can't serve it (outside `[HUB_PROTOCOL_MIN, PROTOCOL_VERSION]`) answers `426 Upgrade Required` with `x-shellglass-hub-version` + `-protocol-min`/`-max` headers, so the operator learns its exact version and which side to upgrade — instead of a misleading 403 on an id that *looks* registered. Because the salt no longer moves, a legit id still authorizes across protocol versions; the 426 check (in `ws_push`, after auth so only a valid key learns the version) is what surfaces the skew. The client echoes the hub's version after neutering it through `proto::neuter` (strip control chars + cap length — the same shared guard `apictl` uses on hub text, since a 426 is peer-supplied). **So bump `proto::PROTOCOL_VERSION` on a breaking wire-message change, NOT the salt** (a purely additive optional key still needs neither, as before); bump `SALT` only if the id derivation itself changes.

Push transport: exactly one active `/push` WebSocket per session. A new connection replaces the old one; close code `PUSH_REPLACED_CLOSE_CODE` tells the evicted protocol-2 client to exit instead of reconnecting. WS self-frames, so there's no length-prefix layer — one WS **Text** message = one wire message (register JSON, then `diff.rs` wire strings), capped at `proto::MAX_WS_MESSAGE`. Client ↔ hub liveness rides on WS ping/pong (axum auto-pongs; the client runs the timeout).

## Conventions

- Deliberate simplifications are marked with `ponytail:` comments naming the ceiling and upgrade path — respect them; don't "fix" a documented shortcut without reason.
- Non-SSE responses are compressed per-route; the SSE stream is never compressed (buffering would defeat realtime push).
- Shelved explorations are kept on `exp/<name>` branches pushed to origin (not deleted), so the code and the findings stay retrievable for future reference. Existing ones: `exp/procedural-glyph-geometry` — kitty-style procedural SVG geometry for box-drawing/block glyphs; shelved because the Nerd Font the default config auto-exports hints straight lines better than stretched-SVG rects can on a fractional device-pixel grid (see the branch's commit for the full reasoning).
